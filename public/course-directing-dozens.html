Module 1 — The Mindset Shift

You're the PM Now

  • Design the work
  • Break it into tasks agents can execute
  • Review what lands
  • Keep the machine fed

The agents are your engineering team. Your job is to make tasks for them. That's it.

Module 1 — The Mindset Shift

Throughput Over Precision

Running 20 agents in parallel means accepting that some work gets done twice, some tasks need a retry, and some output gets edited before it merges.

That's not failure. That's the tradeoff for going 10x faster.

Creation and correction at the speed of thought.

Module 2 — Problem 1 of 4

Agents Forget Everything

  • The context window fills up and the session ends
  • Everything the agent "knew" — the plan, the decisions, the current state — is gone
  • If your work only lives inside a session, it disappears when the session does
The Fix

Work must live outside the session — in git, in a file, in a task system. The session is ephemeral. The work is not. When a new session starts, the agent reads its assigned task and picks up immediately.

Module 2 — Problem 2 of 4

Agents Wait Instead of Work

  • Agents are trained to be polite — they start a session and wait for you to type something
  • At scale with 20 agents, you cannot babysit each one
  • An agent sitting idle is burning time and blocking the queue behind it
The Fix

Every agent needs one rule: "If there is work assigned to me, I run it immediately. No waiting." Agents that check their assigned task on startup and begin working without prompting are the ones that actually scale.

Module 2 — Problem 3 of 4

Parallel Agents Create Merge Chaos

  • 10 agents working the same codebase simultaneously means 10 branches diverging in parallel
  • The last agents to finish are merging against a codebase they've never seen
  • Their changes may not apply cleanly — or may contradict work that already landed
The Fix

A dedicated merge handler — one agent whose only job is to serialize and intelligently merge completed work. It rejects conflicts, reorders when needed, and never lets broken code into main.

Module 2 — Problem 4 of 4

No Visibility

  • With 10+ agents running, you have no idea what's done, what's stuck, and what needs you
  • You're scanning raw output from every session trying to find the signal
  • The activity stream is noise
The Fix

A work-order system. Every task has a status. Every batch of related tasks rolls up into a named unit you can track. You look at the summary — done, in progress, blocked — not the stream.

Module 3 — What You Need · 1 of 3

Persistent Work State

  • Every task stored outside agent memory — in git, in a file, in a lightweight tracker
  • Each item has: what to do, who's doing it, what "done" looks like
  • When a session ends and a new one starts, the agent reads its task and picks up — no re-explaining, no catching up
  • Work that persists through crashes and restarts is work that actually gets done

Sessions come and go. Work stays.

Module 3 — What You Need · 2 of 3

Role Separation

Every scaling agent system converges on these four roles

Role 1

Orchestrator

The one you talk to. Breaks down goals into tasks and assigns them to workers.

Role 2

Workers

Ephemeral. Execute one task, submit the result, go idle. Sessions are cattle.

Role 3

Supervisor

Monitors workers. Detects stuck ones. Escalates to you when needed.

Role 4

Merge Handler

Serializes completed work into main. Handles conflicts. One job only.

Without these roles, you're doing all four manually. That's why you're the bottleneck.

Module 3 — What You Need · 3 of 3

The Propulsion Rule

"If there is work assigned to you, run it. Now. Not after asking. Not after waiting. Now."

Agents that wait for human input kill the system at scale. Agents that check their queue on startup and start working are what make 20-agent fleets possible.

Close — This Week

Three Things to Try This Week

  • Set up a persistent task file for your current project — tasks with clear done criteria, stored in the repo. Not in your head, not in context.
  • Add one rule to your agent prompt: "Check your assigned task first. If you have one, start it immediately without waiting for input."
  • Designate one agent session as merge-only for a 2-hour block. Give it one job: serialize completed branches into main. See what changes.

You don't need a platform to start. You need a practice.
