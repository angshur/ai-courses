Intro · 10 Minutes

The Problem With AI Point Tools

Intro — The Current State

This Is How Most People Use AI

"Copy from ChatGPT. Paste into Notion. Copy from Notion. Paste into email. Repeat 40 times a day."

  • AI tools have created a new kind of busywork: context switching between AI assistants
  • The average knowledge worker now uses 4–6 AI tools — none of which talk to each other
  • You're doing the orchestration manually. That's the job you're trying to eliminate.
  • The next unlock isn't a better AI tool. It's connecting the tools you already have.

The bottleneck isn't the model. It's you in the middle.

Intro — The Shift

Tools vs. Agents: What's Different

AI ToolsAI Agents
You trigger them manuallyThey trigger on events or schedules
One task per promptMulti-step task sequences
You move the output forwardThey pass work to the next step
You're the orchestratorThe system orchestrates itself
10x individual productivity10x workflow throughput

An agent team doesn't replace you. It handles the sequence so you can handle the judgment.

Intro — Scope

What We're Not Building Today

  • Not autonomous AI that runs your company unsupervised
  • Not a coding project — you don't need to write code
  • Not a replacement for human judgment on consequential decisions
  • Not something that requires an AI engineering team

What we are building: a structured workflow where AI agents handle the repeatable steps — and humans stay in the loop at the moments that matter.

The goal is a system you trust, not a black box you pray over.

Module 1 · 20 Minutes

The Anatomy of an Agent Team

Module 1 — Foundations

What Is an AI Agent?

"An agent is an AI that takes actions — not just answers."

  • A chatbot answers a question and waits for your next message
  • An agent receives a goal, breaks it into steps, executes them, and returns a result
  • The key difference: an agent can use tools — search the web, read a file, call an API, write to a database, trigger another agent
  • "Agent team" = multiple agents, each with a specific role, passing work between them

Think of it like hiring a specialized team — researcher, writer, reviewer, publisher — except the handoffs happen in seconds, not days.

Module 1 — The Framework

Three Roles Every Agent Team Needs

Role 1

The Orchestrator

Receives the goal. Breaks it into tasks. Assigns tasks to the right agents. Assembles the final output.

The "manager." Often Claude or GPT-4 with a system prompt that defines the workflow.
Role 2

The Specialists

Each specialist handles one class of task: research, writing, summarizing, validating, formatting, sending.

Can be different models, tools, or API calls — anything that does one thing well.
Role 3

The Reviewer

Checks the output before it goes to a human or triggers the next step. The quality gate.

Catches errors before they compound.

Every agent team that works has these three roles — even if you don't call them by these names.

Module 1 — How It Works

How Agents Pass Work to Each Other

Sequential · most common

A → B → C → Output

Each agent's output is the next agent's input.

Best for: writing pipelines, research summaries, report generation.
Parallel · faster

Orchestrator → [A + B + C] → Assemble

Multiple agents work simultaneously. Orchestrator assembles results.

Best for: analyzing multiple documents, checking multiple sources, generating options.
Conditional · smarter

Orchestrator routes by what it finds

If X → Agent A. If Y → Agent B. If uncertain → escalate to human.

Best for: triage, classification, customer support routing.

Module 2 — The Rule

Where Humans Stay In the Loop

High cost of being wrong → Always add a human checkpoint
Sending an external communicationReview before send
Making a financial decisionReview before action
Publishing contentReview before publish
Escalating to a customerReview before escalation

Low cost of being wrong: Internal research, summarization, first drafts, classification, routing → agents can run autonomously.

The best agent teams are not fully autonomous. They're fast everywhere and careful at the seams.

Module 3 · 20 Minutes

Design Your Agent Team

Module 3 — How to Start

Four Steps to Design Your First Agent Team

  • Pick the workflow — One workflow you run weekly. Repeatable, clear inputs/outputs.
  • Map the steps — List every step in the current workflow. Who does it, how long it takes.
  • Mark the agent candidates — Which steps are repeatable + recoverable if wrong?
  • Draw the handoffs — What does each agent receive? What does it produce? Where does a human check in?

Your first agent team should solve one workflow — not your whole operation. Scope to what you can launch in a week.

Module 4 · 10 Minutes

Build, Test, Evaluate

How you know it's working

Module 4 — Testing

Three Runs Before You Trust It

Run 1 — Happy Path

Give it a perfect input

Does it produce the expected output?

If not: fix the agent that broke the chain before adding complexity.
Run 2 — Edge Case

Give it something unusual

Short input, missing field, ambiguous language. Does it fail gracefully or catastrophically?

If catastrophic: add a validation step before the problem agent.
Run 3 — Adversarial Input

Give it what it shouldn't see

Malformed email, empty document, unexpected language. Does the reviewer agent catch it?

Does the human checkpoint fire when it should?

Three runs tells you more than three weeks of planning.
